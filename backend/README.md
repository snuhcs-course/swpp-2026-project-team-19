# BottleMap Backend

FastAPI service backed by PostgreSQL (RDS in deployed environments). Run commands in this directory.

## Requirements

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/)

## Setup and run

Create your local environment file from the template if it does not exist:

```sh
cp .env.example .env
```

```sh
uv sync
uv run --env-file .env uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`; interactive docs are at `/docs`.
`GET /health` returns `{"status":"ok"}` and does not require a database connection.

For local frontend integration before Supabase Auth is connected, a temporary login endpoint can issue a three-hour development JWT:

```sh
TEMP_AUTH_ENABLED=true \
TEMP_AUTH_JWT_SECRET="replace-with-a-local-secret-at-least-32-characters" \
uv run uvicorn app.main:app --reload
```

Set `TEMP_AUTH_USER_TYPE=operator` in the server environment when launching Uvicorn to exercise operator flows, or `customer` for the default customer identity. The role is configured on the backend rather than supplied by the client. Call `POST /api/auth/temp-login` to receive a bearer token, then pass it as `Authorization: Bearer <accessToken>` to `GET /api/me` and protected APIs. Operator routes can use the `require_operator` dependency. Temporary auth is disabled by default; keep it disabled outside local development. The fixed subject is `local-dev-user`.

## Database configuration

Set these environment variables when database access or Alembic migrations are needed:

Local defaults are in the ignored `backend/.env` file. Run `uv` commands from `backend/` with `--env-file .env` to load them. The username, password, and database must match a local PostgreSQL role and database you create.

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `POSTGRES_HOST` | Yes | — | PostgreSQL hostname, such as the RDS endpoint |
| `POSTGRES_PORT` | No | `5432` | PostgreSQL port |
| `POSTGRES_USER` | Yes | — | Database username |
| `POSTGRES_PASSWORD` | Yes | — | Database password |
| `POSTGRES_DATABASE` | Yes | — | Database name |

Do not commit credentials. Export them in your shell or inject them through the deployment environment.

## Migrations

There are no domain models or initial migration yet. After adding models under `app/models/` and importing them from `app/models/__init__.py`, configure the database variables and run:

```sh
uv run --env-file .env alembic revision --autogenerate -m "describe schema change"
uv run --env-file .env alembic upgrade head
```

Review autogenerated migration files before applying them to a shared or production database.
