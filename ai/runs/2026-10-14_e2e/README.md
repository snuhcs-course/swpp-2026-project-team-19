- **짝 없는 줄의 매칭 결과 (M3a):**

  - 확정·확인 권장된 줄은 모두 제목이 빠진 줄이고, 1순위 상품은 이름상 그 줄의 상품이다(예: `킬커란 12년` → Kilkerran 12, `하쿠슈 DR` → Hakushu Distiller's Reserve). 정답 상품과 맞는지는 짝이 없어 자동으로 채점하지 않았다. 독립병입 줄에서 병입사 제목이 빠지면 정규품으로 확정될 위험이 있다(이번에는 확정된 줄이 산토리·닛카·마르스 정규품 줄이었다). 제목이 빠지면 매칭의 `bottler_missing` 거부권도 작동할 근거를 잃는다.
- **하이브리드 vs 라벨의 차이**는 철자 몇 줄이다. C0 (c) 309 → 310, (d) 41 → 40, C1 (a) 219 → 221, (c) 41 → 39. CLOVA 표기(인쇄대로)와 라벨 표기가 다른 줄에서 S1–S3·M3a 결과가 조금 달라졌다.

- 작성자(Claude)는 P11·P12에서 test 사진의 오류(Beck_04 행 밀림, 미라보 제목 규칙, 크라이넬리시)를 알고 있었다. 프롬프트는 v3 행 정렬 규칙 + 사진 근거 규칙만 더했고 test에 맞춘 문구는 없지만, 블라인드는 아니다.
- 종단 매칭은 r1 하나씩이다. E1·CLOVA+LLM은 회차 간 편차가 크다(CLOVA+LLM 0.821–0.956). r1은 두 조건 모두 가장 낮은 회차라 종단 차이가 크게 보일 수 있다.
- 짝 없는 줄의 매칭 정답 여부는 채점하지 않았다(정답 연결 없음).
- 가격 같은 줄 판정과 `source_lines` 판정은 텍스트 규칙이라 근사다.

## 파일과 재현

- `hybrid_smoke/`, `hybrid_val_v1/`, `hybrid_val_v1_rerun/`, `hybrid_test_v1/`(r1–r3, `manifest_r1.json`은 r1 실행 때, `manifest.json`은 r2·r3 실행 때 것, 둘 다 같은 프롬프트 SHA-256 `b73f15d2…`), 각 `scores.json`
- `match/`: 입력별 종단 매칭 결과(`*_test.json`, `*_beck.json`), 짝지어진 줄 정답 파일(`*.paired_gold.json`)
- `m3_cache/`: M3a 응답 캐시, `report_numbers.json`: 이 문서의 숫자
- Gemini 3.5 호출: 스모크 1 + val 18 + test 42 = 61회(실행당 최대 28), 실패·재시도 0. CLOVA 새 호출 0.
