## 2. 알게 된 것

1. **후보 자체의 품질이 낮다.** P28 처음 25줄 중 사람이 same으로 본 것은 9줄이고, 나머지는 글 조각("라인업 8", "나가하마 붐을")이나 다른 상품이었다. 판정 단계가 이것을 걸렀지만 검토 비용은 그대로 남는다.
2. **LLM 판정은 쓸 만하지만 자동 등록에는 못 쓴다.** 두 모델 모두 에디션·라인 이름이 빠진 표기(`카발란 올로로소`, `고든 앤 맥페일 디스커버리 밀튼더프 10`)에서 틀렸다. P28 사전 등록 기준으로 보류.
3. **직접 생성한 표기가 사람이 승인한 Naver 별칭의 절반을 오탐 없이 덮는다.** P28 상품 40개에 대해 Claude가 Naver 결과 없이 상품당 4~6개 한국어 표기(총 208개)를 만들었다. 사람이 same으로 본 Naver 별칭 49개 중 26개(53%)가 정규화 후 일치했고, 사람이 different로 본 후보와 일치한 생성 표기는 0개였다.
   - 놓친 23개 대부분은 뒤에 수식어가 붙은 형태(`… 에디션`, 빈티지 연도, `… 캐스크`, `배치1`)로, 메뉴 매칭에서는 S2·M3a가 처리하는 영역이다.
   - Naver만 찾은 실제 철자·줄임 변형은 10개 안팎이다(애스케이그, 오챠드, 글랜드로낙, 앰버스, `닛카 타케츠루`, `폴 존 페드로 히메네즈` 등).
   - 기록: 레포 밖 `Bottlemap_P14/p28_claude/gen_aliases.json`
4. **비용:** Naver 경로는 상품당 Naver 질의 여러 번 + 후보마다 LLM 1회 + 근거를 읽는 사람 검토가 필요하다. 생성은 상품(또는 브랜드)당 1회이고 근거 없이 표기만 확인하면 된다.

## 3. 결정과 I3로 넘기는 것

- 대기열 `review/p36_alias_queue.csv`와 Claude 판정 455건(same, `p47_only` 제외)은 **승인하지 않고 보관**한다. 필요하면 I3에서 "생성이 놓친 표기" 후보로 다시 쓴다.
- I3 첫 실험 후보: 카탈로그에 생성 별칭을 넣고 dev 매칭(S1+S2b+S3)의 직접 등록 줄 수 변화를 잰다(API 0회). 검토 단위는 상품이 아니라 브랜드 표기표(약 200개) + 연수·에디션 템플릿.
- 고객 검색(한국어 검색어)도 같은 별칭을 쓰므로 함께 확인한다.
- `p47_only` 상품 181건은 P47 이후에만 다룬다.
