## 1. 경로 정의 (정답 없이 결과만으로 정함)

| 경로 | 결과 | 읽는 법 |
| --- | --- | --- |
| `alias_exact` | exact, 별칭 점수 1.0 | 정규화 후 별칭 정확 일치 (S1 괄호·병기 변형 포함) |
| `s2_exact` | exact, 점수 0.8 | S2 브랜드+연수+에디션, S2b 기본 상품 |
| `s3_exact` | exact, 점수 0.6 | S3 편집거리(숫자 있는 이름, 거리 ≤ 1, 후보 1개) |
| `multi` | multi | S1 한 줄 두 상품 |
| `s2b_confirm` / `s3_confirm` | ambiguous, 후보 1개 확인 권장 | S2b(에디션 미기재 1개) / S3(편집거리 1개) |
| `m3a_confirm` / `m4_confirm` | ambiguous, 1순위 LLM 후보 확인 권장 | M3a 번역 / M4 Naver 판정. **규칙이 이미 확인 권장한 상품에 LLM이 동의한 줄은 규칙 경로로 셈**(M3 README와 같은 기준) |
| `llm_top` | LLM 후보가 1순위, 확인 권장 없음 | 짧은 토큰 미검증, 현재 후보 밖 상품 등 |
| `single` / `choose` | 규칙 후보 1개(확인 권장 없음) / 여러 개 | 업주 선택 |
| `register` | 후보 없음 | 업주 직접 등록 |

"정답"은 exact·multi는 정답 상품(한 줄 두 상품 중 하나만 맞은 partial 포함, 다른 상품이 아니므로), 확인 권장·선택은 1순위가 정답 상품, `register`는 정답이 카탈로그에 없거나 `unknown`·`non_whisky`(붙일 상품이 없는 것이 맞음).

## 3. 등급과 정책안

등급: **A** 자동 확정(업주가 아무것도 안 함, 틀리면 그대로 게시) · **B** 확인(제안 1개를 한 번 눌러 수락) · **C** 선택(후보 목록에서 고름) · **D** 직접 등록.
모든 정책에서 `llm_top`·`single`·`choose`는 C, `register`는 D. 지금 백엔드 메뉴 등록은 아직 `resolve_product`(단계 없음)를 쓰므로 세 정책 모두 현재 서비스 동작이 아니라 P22·M3를 붙인 뒤의 안이다.

## 6. 정책별 trade-off

**P1 LLM 확인 = B (M3 원칙 그대로)**
- 장점: LLM이 낸 상품은 항상 업주가 한 번 본다. test에서 나온 LLM 확인 권장 오답(C0 2줄, C1 1줄)은 게시 전에 막을 기회가 있다.
- 비용: B가 가장 많다(full C1 21줄, 사진당 확인 포함 2.08). 업주가 "확인"을 습관적으로 누르면 B 오답을 거르는 효과가 줄어든다(이 효과는 측정하지 않았다).

**P2 LLM 확인 자동 수락 (m3a/m4 확인 권장 = A)**
- 장점: full C1에서 B가 21 → 8, 확인 포함 사진당 2.08 → 1.08. C+D(업주가 고르는 줄)는 P1과 같다.
- 비용: LLM 오답이 업주 확인 없이 게시된다. dev 오답 0이지만 dev n=13(C1)의 95% 상한은 20.6%이고, test에서는 C0 7/9, C1 193/194였다. P18 (e)의 false merge 기준 0.02는 dev로 증명할 수 없다.
- P29 원래 질문(자동 확정 임계값)에 가장 직접적인 안이다. M3a는 신뢰도가 없어 경로 단위로만 정할 수 있다.

**P3 별칭만 자동 (S2/S3 exact = B, LLM 확인 권장 = C)**
- 장점: A는 별칭 정확 일치(dev 오답 0, C1 n=138, 상한 2.1%)뿐이라 자동 게시 오답 위험이 가장 낮다.
- 비용: C+D가 가장 많다(full C1 사진당 1.46, 최대 8, 5개 미만 12/13). M3a·M4가 줄여 준 부담이 "선택"으로 돌아온다. S2 exact도 B가 되어 확인 포함 사진당 3.00.

**공통**
- C0에서는 세 정책의 C+D 차이가 작다(2.54~3.08). 새 상품이 많은 바에서는 등급 정책보다 카탈로그 범위가 부담을 정한다.
- 정책 간 차이를 오답으로 비교하려면 오답이 나오는 데이터가 필요하다. dev는 모든 경로가 오답 0이라 이 표만으로는 위험 차이가 보이지 않는다. 다른 바(새 held-out)에서 경로별 오답 수를 재는 것이 `naver_plan.md` 6절 (e)의 계획과 같다.
- 수치는 dev에서 조정한 규칙(S2b·S3·M3a 거부권)과 M4 판정으로 낸 것이라 낙관적이다.
