- **반복:** rules는 (구성, 카탈로그, 입력)마다 1회. rules+LLM은 3회(r1–r3). 회차마다 빈 응답 캐시에서 시작하고 회차끼리 캐시를 공유하지 않는다(공유하면 같은 응답이 돌아와 3회가 1회가 된다). 종단은 추출 r*i*에 LLM 회차 r*i*를 짝짓는다(3쌍).
- **오류:** 어댑터가 실패를 돌려준 요청은 하네스가 3번 더 보낸다. 그래도 실패하거나 JSON 형식·스키마가 틀리면 서버와 같이 "답 없음"(그 줄은 rules 결과)으로 채점하고 건수를 적는다(`engine_stats`). 할당량 오류나 호출 상한에서는 그 회차를 멈추고 미완료로 표시한다. 같은 캐시로 다시 실행하면 빠진 요청만 보낸다. 결과를 보고 재실행하거나 회차를 고르지 않는다.
- **호출 수:** 예상 상한 라벨 입력 33장 × 카탈로그 2 × 3회 = 198, 종단 198, 합계 396. 실행 명령 1회당 250회(`--max-calls`)를 넘으면 멈춘다. 하루 한도 때문에 나눠 돌리면 이미 끝난 회차는 다시 돌리지 않는다.
- **순서:** 실행 전 점검 → rules 전부 → rules+LLM r1, r2, r3 → 채점 → `ai/runs/<날짜>_p10/`에 결과 JSON(구성 해시·카탈로그 digest·정답 해시가 들어 있음)과 README.

### 4.4 지표

**용어.** 줄 = 위 입력의 한 줄. 상품 줄 = 정답이 상품 key·`new:`·`both:`인 줄. 카탈로그 K에서 알려진 줄 = 정답 상품이 모두 K에 있는 상품 줄. 확정 = `exact_match` 또는 `multi`. 확인 권장 = `ambiguous`이고 1순위 후보 `evidence.confirmRecommended = true`(규칙 S2b·S3·E1과 LLM 모두).

| 지표 | 정의 | 기준 |
|---|---|---|
| **NFR-3 알려진 상품 Top-1** | 알려진 줄 중 자동 확정이 정답인 줄 ÷ 알려진 줄. `exact_match`는 제안 상품이 정답, `both:` 줄은 `multi`의 상품이 정답 상품 전부와 같을 때만(두 상품·세 상품 모두). 확인 권장이나 1순위 후보는 정답이어도 세지 않는다 | ≥ 0.90 |
| **NFR-4 false merge (FM)** | (false_merge + overconfident) ÷ 전체 줄. false_merge = 확정했는데 정답 상품이 아님(카탈로그에 없는 상품·`non_whisky` 줄을 확정한 경우 포함). overconfident = 정답 `unknown` 줄을 확정 | ≤ 0.02 |
| 수락 시 오답률 | (FM 줄 + 틀린 확인 권장 줄) ÷ 전체 줄. 틀린 확인 권장 = 확인 권장 1순위가 정답 상품이 아님(정답이 그 카탈로그에 없음·`unknown`·`non_whisky` 포함). 업주가 확인 권장을 전부 받아들였을 때 틀린 줄의 비율 | 기준선 0.02 (NFR 아님, 아래 조치 규칙) |
| 업주가 볼 줄 (사진당) | 확정되지 않은 줄을 아래 넷으로 나눠 메뉴 줄이 있는 사진 수로 나눈다(`burden_kind`). **어려운 줄 = (b) + (c) + (d)** | 참고 목표: 어려운 줄 5 미만 |
| 포함률 | 상품 줄 중 정답 상품(`both:`는 모두)이 그 카탈로그에 있는 줄 ÷ 상품 줄 | 없음 |

업주가 볼 줄의 네 종류:
- (a) 확인: 후보 1개이고 그것이 정답, 또는 확인 권장 1순위가 정답.
- (b) 선택: 후보가 여럿이고 확인 권장이 없으며 정답이 후보 안에 있음. 정답 `unknown` 줄의 후보 목록도 여기.
- (c) 새 상품 등록: 후보 없음(`unmatched`). 정답이 카탈로그에 없는 줄이면 이것이 맞는 처리다.
- (d) 오답: 후보 안에 정답이 없음(`ambiguous_bad`), 또는 확인 권장 1순위가 정답이 아님.
- FM 줄은 확정이라 (a)–(d)에 들어가지 않는다. 업주가 보지 못하는 오답이다.

**판정 (이 규칙으로만 한다).**
- 대상: **C2 rules+LLM, 라벨 입력.** NFR-3은 `full`에서, NFR-4는 `full`과 `asis` 둘 다에서 만족해야 한다.
- 대표값은 3회 평균이고 최솟값·최댓값을 같이 적는다. 기준과의 비교는 반올림 전 값으로 한다.
- LLM 층은 확정을 만들지 않으므로 Top-1과 FM은 rules와 같아야 한다(3회 모두). 다르면 구현 오류로 보고 원인을 적고, 판정은 rules 값으로 한다.
- `asis`의 Top-1은 분모가 카탈로그에 있는 줄로 줄어든 값이라 NFR-3 판정에 쓰지 않는다. 포함률과 함께 보고한다.
- 종단 숫자는 같은 정의로 함께 보고하고 판정에 쓰지 않는다. 종단 Top-1은 놓친 정답 줄을 실패로 센다(`e2e_plan.md`, 하네스 `top1_missed_as_fail`).

**수락 시 오답률 조치 규칙 (사전 등록, 2026-10-29 박진우 결정).**
- `asis`의 C2 rules+LLM 수락 시 오답률 **3회 최댓값이 0.02를 넘으면**, 서버 LLM 층을 켤 때(D9) **LLM 후보에는 확인 권장 표시를 붙이지 않는** 안을 팀에 올린다. LLM 후보는 후보 목록에 남기되 "탭 한 번 확인"으로 보이지 않게 한다.
- 이유: LLM 층은 카탈로그에 진짜 술이 없을 때 가까운 형제 상품을 하나 찾아 확인 권장을 붙인다(dev `eval_dropprod`에서 LLM 확인 권장 57줄 중 9줄 오답, 시그나토리 독립병입 5줄 등). 업주가 믿고 누르면 틀린 술이 게시된다.
- `full`만 넘는 경우는 조치 대상이 아니다(업주가 만나는 상태가 아님). 0.02 이하이면 지금 설계대로 간다. 판정 결과와 별개로 LLM 확인 권장의 정답 비율(출처별)은 늘 보고한다.

**함께 보고 (판정에 쓰지 않음).**
- 모든 구성 × 카탈로그 × 입력의 위 지표, 바별 숫자(015·016은 따로), 사진당 어려운 줄 5 미만인 사진 비율.
- 구성 간 차이: C0 → C1(P17 별칭), C1 → C2(E1/E2). dev `eval`은 생성 별칭을 빼고 쟀으므로 P17의 첫 깨끗한 측정이고, E2 용어 사전도 `eval_plan.md` A4 절이 "깨끗한 측정은 I3 test(P10)"라고 미뤄 둔 것이다.
- 확인 권장을 낸 쪽(규칙 / LLM)별 건수·정답 수, (c) → 후보로 올라온 줄과 그중 정답이 후보에 있는 줄, 거부권이 막은 후보.
- LLM: 회차별 호출 수, 오류·형식 오류·답 없음 사진 수, 사진당 지연(평균·p50·p95). 토큰 수는 서버 어댑터가 돌려주지 않아 기록하지 않는다.
- 종단: 놓친 정답 줄, 짝 없는 추출 줄의 결과 분포(확정·확인 권장은 "근거 없는 확정"으로 따로 셈).
- **목록 밖 독립병입사 줄 (4.8 참고).** 정답의 새 상품 brand나 `raw_name`이 `IB_BOTTLERS`(12곳)에 없는 병입사인 줄을 실행 전에 정답 파일에서 뽑아 고정하고, `asis`·`full` 각각 아래를 적는다. (1) 줄별 결과(후보 없음 / 후보만 / 확인 권장 / 규칙 확정) (2) `asis`에서 공식(증류소) 제품에 확인 권장이 붙은 줄 수 (3) `full`에서 정답 새 상품의 순위와 공식 제품이 1위인 줄 수 (4) 거부권 기록과 LLM 번역의 `bottler_en` (5) 병입사가 줄 뒤나 괄호에 적힌 줄을 규칙 S1이 공식 제품으로 확정했는지.

### 4.8 결과 전에 알려진 한계 (고치지 않고 결과와 함께 보고)

- **LLM 층은 NFR-3·NFR-4를 바꾸지 못한다.** 확정을 만들지 않으므로 Top-1과 FM은 rules가 정한다. LLM 층의 효과는 (c)를 (a)·(b)로 바꾸는 것과 수락 시 오답률에만 나타난다.
- **dev 기준 예상:** NFR-3(≥ 0.90)은 미달할 가능성이 크다(dev C2 최고 0.771, `service`). NFR-4는 통과할 가능성이 크다(dev C2 FM 0). 결과가 아니라 결과 전 예상이다.
- **`full`의 추가 상품은 영문 표준명 별칭 하나뿐이다.** 카탈로그 상품과 달리 생성 한국어 별칭이 없어 한글 표기 줄이 잘 확정되지 않는다(I2 test에서 C1 Top-1이 C0보다 크게 낮았던 이유와 같음). 추가 상품에 생성기를 돌리는 것은 8곳 별칭 작업이라 하지 않는다.
- **`asis` Top-1은 분모가 작고 흔한 상품 쪽으로 치우친다.** NFR-3과 비교하지 않는다.
- **dev에서 만든 규칙과 별칭:** E1/E2 규칙과 P17 생성기는 dev 오류를 보고 만들었다. dev FM 0은 낙관적인 값이다. 8곳이 이들의 첫 깨끗한 측정이다.
- **목록 밖 독립병입사:** LLM 층의 `bottler_missing` 거부권은 병입사 이름을 `IB_BOTTLERS`(12곳)에 대조한다. 정답을 만들다 8곳에서 목록에 없는 병입사(Hannah Whisky Merchants, Hart Brothers, Whiskynavi, Liquid Treasures, Legacy, unknown 줄의 Whisky Broker, Sansibar)가 나왔다. 이 줄에서는 거부권이 작동하지 않아 공식 제품이 LLM 후보·확인 권장으로 나올 수 있다. 8곳을 보고 목록을 고치면 test를 보고 바꾼 셈이라 고치지 않고, 4.4의 분석으로 따로 보고한다. 목록 대신 "번역에 병입사가 있나"로 거르는 안은 I4 실험이다.
- **연림 두 지점(015·016):** 메뉴가 겹칠 수 있어 바별 숫자가 독립이 아니다.
- **정답:** 라벨러 A·B·C가 모두 Claude라 같은 연결 실수를 같이 할 수 있다. 박진우 검수로 줄이지만 FM 판정은 정답 품질에 기대고 있다.
