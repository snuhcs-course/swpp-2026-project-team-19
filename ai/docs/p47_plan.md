## 2. 데이터

- **카탈로그:** `ai/catalog/catalog_v2_eval_5bars.json` (이 브랜치에서 만든다). 수이·오드바 정답 상품은 들어 있고, 출처가 `menu:수이`·`menu:오드바`뿐인 별칭은 뺀다. "상품은 DB에 있고 이 메뉴판 표기는 처음 본다"는 C1과 같은 상태다. 카탈로그는 데이터이고 매칭 규칙이 아니다.
  - 보조: `--drop-products` 스냅샷(수이·오드바에서만 나온 상품까지 뺀 것)으로 새 상품 판정을 따로 잰다. 보조 표로만 보고한다.
- **정답:** 1층 `eval/labels_final_v1.json`(가이드라인 v2.3), 2층 `eval/match_gold_final_v1.json`(split `"final": ["수이", "오드바"]`). 박진우 검수를 반영한 뒤 P47 전에 확정한다.
- **사진 사용 제한:** P47 전까지 수이·오드바 사진으로 Gemini 추출, 하이브리드 추출, 매칭을 돌리지 않는다. 예외는 라벨 검수용 CLOVA OCR 캐시 하나(가이드라인 v2.3 "검수 전 OCR 대조")다. P47 하이브리드 추출은 이 캐시를 그대로 쓰고 CLOVA를 다시 부르지 않는다.

## 3. 실행

- 수이·오드바 사진 전부 × 1회(r1). 결과를 보고 재실행하거나 회차를 고르지 않는다. API 오류로 응답이 없을 때만 재시도 정책(E1과 같음)을 따른다.
- 순서: CLOVA 캐시(표 인식 off) → 하이브리드 추출 v1 → S1+S2b+S3 → M3a(합치기). 정답 줄 맞추기·지표 계산은 `e2e_match.py`와 같다.
- 라벨 입력 기준선(줄 = 정답 줄)도 같은 카탈로그·매처로 한 번 계산해 나란히 적는다.

## 4. 지표 (`eval_plan.md`와 같은 정의)

- **추출:** 항목 정답률(이름 짝 + 가격 + unit, 대표), 가격 정확도, 항목 F1(엄격·관대). 짝짓기는 `eval_plan.md` 항목 대응 규칙.
- **알려진 상품 Top-1:** 라벨 입력 Top-1과 종단 Top-1(놓친 정답 줄은 실패, `e2e_plan.md` 정의).
- **false merge 비율:** false_merge + overconfident, 줄 단위(잔·병 중복 제거).
- **사진당 업주가 볼 줄 수:** 확정(exact·multi)이 아닌 줄을 (a) 확인 (b) 선택 (c) 직접 등록 (d) 오답 후보로 나눠 사진당 집계, 놓친 정답 줄과 짝 없는 추출 줄 중 확정되지 않은 줄도 사진당으로 같이 적는다.
- **지연:** 사진당 CLOVA(캐시에 기록된 원래 호출 지연) + 하이브리드 Gemini + M3a를 따로, 평균·p50·p95.
- 바별(수이·오드바) 숫자를 따로 적는다.
