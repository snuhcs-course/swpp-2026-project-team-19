# E2E (I2) 사전 등록: 하이브리드 추출 → M3a 매칭, 종단 점검

2026-10-14 · 박진우 (작성: Claude Code) · 브랜치 `i2-e2e-hybrid` (base `i2-m3-llm-match` 7731422) · API 호출 전에 커밋

**질문.** (1) 사진 + CLOVA 줄을 함께 주는 하이브리드 추출은 E1(사진만)·CLOVA+LLM(줄만)과 비교해 어떤가. (2) 라벨 대신 실제 추출 결과를 S1+S2b+S3 → M3a에 넣으면 매칭 지표가 얼마나 떨어지는가.

**판정 기준 없음.** 이번 작업은 점검(종단 확인)이다. 채택·기각 판정을 하지 않고 숫자와 사례를 보고한다. 아래 정의는 결과를 보기 전에 정하고, 결과를 보고 바꾸지 않는다.

**정답.** 추출 채점은 라벨 v1.1(`score.py --set val_v1_1 / test_v1_1`). 매칭 정답은 `eval/match_gold_v1_1.json`(라벨 v1.1과 항목 순서·이름이 같다).

## 1. 하이브리드 추출 (`ai/ocr/hybrid.py`)

- **입력:** 전처리된 사진(E1과 같은 바이트) + CLOVA 줄. CLOVA는 캐시(`data/ocr_cache/`, 표 인식 off)만 쓰고 새 호출은 0회. 줄은 P12 v3과 같은 형식(`L012 [x0,y0,x1,y1] 텍스트`, CLOVA 순서, 가로 간격 2.5 × 줄 높이에서 나눔).
- **프롬프트 v1:** E1 프롬프트 v2의 규칙·텍스트 예시 + "글자 철자와 가격 숫자는 OCR 줄을 근거로, 줄 구조와 제목·섹션은 사진을 근거로" + P12 v3의 좌표·행 정렬 규칙 + `source_lines` 규칙. 예시는 가이드라인 텍스트 예시만 쓴다(평가셋 사진·라벨 내용 없음, 단위 테스트로 검사).
- **출력:** E1 스키마(raw_name, price_krw, pour_ml, unit) + `source_lines: {name: ["L012", ...], price: ["L040", ...]}`. name = raw_name에 들어간 글자의 OCR 줄(브랜드 제목 줄, 한/영 두 줄 포함), price = 그 항목 가격 숫자의 OCR 줄. 가격이 null이거나 OCR 줄에 없으면 빈 목록.
- **모델:** `gemini-3.5-flash-lite`, thinking `medium` (E1 조건 A2와 같음). 재시도 정책·타임아웃은 E1과 같다.
- **프롬프트 조정:** val(9장)에서만, 최대 1회(v1 → v2). v2를 만들면 val 1회를 다시 돌리고 val 항목 정답률이 v1 이상이면 v2, 아니면 v1을 test에 쓴다. test 결과를 보고 프롬프트를 바꾸지 않는다.
- **test:** 14장 1회(r1) → `score.py --set test_v1_1`. 시간이 되면 r2·r3을 같은 프롬프트로 추가한다(추가 여부는 r1 결과와 무관하게 남은 시간으로만 정한다).
- **호출 한도:** `gemini-3.5-flash-lite`는 실행(명령 1회)당 API 호출 80회(재시도 포함), 넘으면 멈추고 보고.
- **지연:** 사진당 = CLOVA 지연(캐시에 기록된 원래 호출 지연) + Gemini 지연. 둘 다 따로 보고.

### 누락 감지 (사진마다 기록)

- **가격처럼 보이는 줄:** OCR 줄에서 통화 표시(₩, W, 원, won, KRW, k)와 구분 기호(`/`, `|`, `-`, `~`, 공백)를 뺀 나머지가 전부 숫자 토큰이고, 그중 하나 이상이 가격 범위에 드는 줄. 숫자 토큰 = `1,234`꼴, `12.5`꼴, 정수. 가격 범위 = 소수(1–999), 쉼표 천 단위, 정수 10–999(약식) 또는 1,000–9,999,999(단, 1900–2030은 연도로 보고 제외). `ml`·`년`·`yo` 같은 글자가 붙으면 가격 줄이 아니다.
- **기록:** 어느 항목의 `source_lines`(name·price)도 가리키지 않은 가격 줄 수(`uncited_price_lines`)와 전체 가격 줄 수.
- **표시 규칙:** `uncited_price_lines ≥ max(4, 0.2 × 가격 줄 수)`인 사진을 "누락 의심"으로 표시한다. 비위스키 섹션의 가격은 정상적으로 인용되지 않으므로 오탐이 있을 수 있다.
- **확인:** 표시된 사진과 실제로 많이 놓친 호출(라벨 항목의 30% 이상 누락)을 대조해 보고한다.

### `source_lines` 정확도 (test r1, 라벨 항목과 짝지어진 하이브리드 항목)

짝짓기는 score.py(엄격 → 관대, unit 일치). 정답 근거 줄 라벨은 없으므로 텍스트로 판정한다. 비교는 `score.normalize`(소문자, 공백·문장부호 제거) 후.
- **이름 정밀:** 인용한 name 줄이 하나 이상이고, 각 줄의 텍스트(가격 토큰 제거)가 라벨 raw_name 안에 들어 있다(줄 길이 10%까지, 최소 1글자 편집 허용하는 부분 문자열 일치).
- **이름 완전:** 이름 정밀 + 인용한 줄들을 이은 텍스트(인용 순서 또는 y 순서 중 가까운 쪽)가 라벨 raw_name과 편집거리 max(1, 10% 길이) 이내.
- **가격 숫자:** 라벨 가격이 있는(note 없는) 항목 중, 인용한 price 줄 하나 이상에 ×1·×1,000·×10,000(마침표 천 단위 `290.000` 포함)으로 라벨 가격이 되는 숫자가 있음.
- **가격 같은 행:** 가격 숫자 + 그 줄의 세로 중심이 인용한 마지막 name 줄의 세로 중심에서 1.5 × 줄 높이(그 name 줄 높이) 이내.

## 2. 종단 매칭 (`ai/eval/e2e_match.py`)

- **추출 입력 3개 + 기준:** E1 test r1(`2026-10-13_test_v2_A2`), CLOVA+LLM test r1(`2026-10-14_p12_clova/test_v3_parse`), 하이브리드 test r1. 기준은 라벨 입력(줄 = 정답 줄), 같은 코드로 계산하고 `ai/runs/2026-10-14_m3/test_m3a.json`과 숫자가 같은지 확인한다.
- **매처:** S1+S2b+S3 → M3a(합치기). 코드·프롬프트·규칙은 동결 커밋 `1ace927` 그대로(`ai/match_llm/`, `match_eval.py`의 판정 함수 재사용, 수정 없음). M3a 대상 = S1+S2b+S3가 C0 또는 C1에서 확정하지 않은 줄, 사진당 1회 호출.
- **추출 줄:** 사진마다 추출 항목의 raw_name을 출력 순서대로 중복 없이(잔·병 항목은 한 줄).
- **정답 줄에 맞추기:** 사진마다 score.py `match_photo`로 라벨 v1.1 항목과 추출 항목을 짝짓는다(unit 일치 엄격 → 관대, 남은 것은 unit 무시 재짝 = score.py의 잔·병 혼동 짝). 라벨 항목 i의 정답 = match gold 항목 i. 추출 줄의 정답 = 그 줄 항목이 짝지어진 라벨 항목의 정답(여럿이면 라벨 순서 첫째, 충돌 수 기록).
- **분모:** test split(미라보 9장 + 포레스트 1장 = 10장, 정답 478줄). Beck 4장은 match gold에서 dev(M3 개발에 쓴 사진)이므로 **보조 표로만** 따로 보고한다.
- **지표 (C0·C1, 짝지어진 추출 줄):** 알려진 상품 Top-1, false merge rate, 업주 부담 (a) 확인 (b) 선택 (c) 직접 등록 (d) 오답 후보, LLM/규칙 확인 권장 정답 비율, 확인 권장 수락 시 오답률. 정의는 `match_eval.py`와 같다.
- **추가 지표:**
  - **종단 Top-1:** 알려진 상품 정답 줄 중, 그 줄에 짝지어진 추출 줄이 하나라도 정답 exact인 비율(놓친 줄은 실패). 라벨 입력 Top-1과 같은 분모라 직접 비교된다.
  - **놓친 정답 줄:** 어느 추출 항목과도 짝지어지지 않은 정답 줄 수.
  - **짝 없는 추출 줄(지어낸 줄):** 줄 수와 매칭 결과 분포(확정 exact/multi, 확인 권장, 후보 여럿, unmatched). 정답이 없으므로 확정·확인 권장은 "근거 없는 확정" 위험으로 따로 센다.
  - **사진당 업주 부담:** (a) 따로, (b)+(c)+(d) 따로(짝지어진 줄). 짝 없는 줄 중 확정되지 않은 줄 수, 놓친 정답 줄 수(업주가 직접 추가해야 함)도 사진당으로 같이 보고.
- **호출 한도:** `gemini-3.1-flash-lite`(M3a)는 실행당 60회, 넘으면 멈추고 보고. 응답 캐시는 `ai/runs/<날짜>_e2e/m3_cache/`(라벨 입력은 기존 `2026-10-14_m3/cache`를 캐시만으로).
