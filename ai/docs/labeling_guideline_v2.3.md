# BottleMap 메뉴 라벨링 가이드라인 v2.3

2026-10-14 · 박진우 (AI 담당) · v2.2(2026-10-12)에 검수 절차만 추가. 라벨 규칙은 v2.2와 같다

메뉴판 사진 한 장에서 정답 항목 목록을 만드는 규칙이다. **추출 프롬프트도 같은 규칙을 따라야 공정한 채점이 된다.**

- 대상은 1층(추출) 라벨뿐이다. 제품 매칭(product_id)은 카탈로그 확정 후 따로 다룬다.
- 2026-10-14부터 평가에는 표기를 인쇄대로 고친 v1.1(`eval/labels_v1_1.json`, `eval/labels_heldout_v1_1.json`, 변경 내역 `eval/labels_changelog.md`)을 쓴다. 아래 설명의 v1 파일은 수정하지 않고 남겨 둔다.
- val 셋(`eval/labels_v1.json`, 위스키복춘·서로상)은 v2.1로, test 셋(`eval/labels_heldout_v1.json`, 미라보·Beck·포레스트)은 v2.2로 만들었다. 두 셋의 차이는 v2.2에서 추가한 규칙뿐이고, val 라벨에는 v2.2 추가 규칙에 해당하는 항목이 보이지 않는다 (219항목 모두 제품명 전체가 한 줄에 있고 잔/병이 명시됨. 사진 재확인은 하지 않음).
- test 셋 사진은 이 가이드라인을 다듬는 데 썼다(새 경우를 발견한 곳이 test 사진이다). 규칙만 추가했고 프롬프트·별칭은 test 사진으로 만들지 않는다.

## v2.2 → v2.3 변경 (2026-10-14)

규칙은 바꾸지 않았다. raw_name은 v2.1부터 "메뉴판에 적힌 그대로"였지만, test 라벨 44항목(미라보·포레스트)과 val 2항목이 표준 표기로 적혀 있었다(예: 인쇄 "캐스크 스트랭스" → 라벨 "스트렝스"). 사람 검수에서 이를 걸러내지 못했다. 그래서 검수 전에 OCR과 대조하는 절차를 추가한다(아래 "검수 전 OCR 대조").

## v2.1 → v2.2 변경 (2026-10-12)

| 경우 | v2.2 규칙 |
| --- | --- |
| 브랜드·증류소·병입사 제목 아래 줄에 연수·에디션만 적힘 | raw_name = **가장 가까운 브랜드·병입사 제목(적힌 그대로) + 공백 + 줄**. 지역(하이랜드 등)·국가·카테고리(블렌디드 등) 제목은 붙이지 않는다 |
| 메뉴 어디에도 잔/병 표기가 없음 | 가격대로 판단해 unit을 채운다(바 잔 가격대면 glass). 항목 note는 쓰지 않고 라벨 파일 상단 `unit_basis`에 판단 근거를 적는다 |
| 잔 용량 열이 둘 (예: Glass 30ml / 45ml) | glass 항목 2개, pour_ml로 구분 |
| 정가 취소선 + 할인가 | 할인가를 price_krw로 쓴다 |
| note의 효과 | `ai/eval/score.py`는 note가 있는 항목을 가격 채점에서 뺀다. 가격이 확실하면 note를 쓰지 않는다 |

## 라벨 필드

항목 하나당 5개 필드. 빈 값은 JSON `null`.

| 필드 | 형식 | 규칙 |
| --- | --- | --- |
| raw_name | 문자열 | 메뉴판에 적힌 그대로. 오타·띄어쓰기도 고치지 않는다. 한/영 병기는 `한글 / 영문`으로 둘 다 |
| price_krw | 정수(원) | 실제 원 단위로 환산. 가격 없음·시가·해석 불가면 null |
| pour_ml | 정수(ml) | 해당 항목에 적용되는 용량이 명시돼 있을 때만. 없으면 null |
| unit | `glass` / `bottle` | 항목 줄, 열 제목, 섹션 제목 중 명시된 것 |
| note | 문자열 | 평가셋 라벨 전용. 판단이 애매해 값을 비운 이유. **모델 출력에는 넣지 않는다** |

## 항목 규칙

메뉴판에 줄로 적힌 단일 제품·단일 가격만 항목이다.

**항목으로 본다**
- 술 이름이 적힌 줄. 가격이 없어도 항목으로 만든다(price_krw null)
- 한 줄에 잔·병 가격이 모두 있으면 unit별 항목 2개로 나눈다. 한쪽이 `-`이거나 비어 있으면 그 unit 항목은 만들지 않는다

**항목으로 보지 않는다**
- 세트·테이스팅 플라이트
- 각주로 계산되는 항목 (예: "하이볼은 잔술가격 + 3000원"으로 하이볼 항목을 만들지 않는다)
- 지역·카테고리 섹션명, 열 제목, 테이스팅 노트, 안내문, 로고·워터마크
- **비위스키 섹션:** 섹션 제목(상위 제목 포함)의 카테고리가 **전부** 아래 목록에 해당하면 그 하위 항목은 제외한다
  - 칵테일, 하이볼, 코냑·브랜디, 진, 럼, 보드카, 데킬라, 와인, 맥주, 사케, 리큐어, 논알콜, 안주·푸드
  - 섞인 제목(예: `COGNAC / BLENDED / IRISH`) 아래 항목은 **유지**한다
  - 목록에 없거나 판단이 안 서는 제목은 유지한다
  - **이름만 보고 술 종류를 판단하지 않는다**
  - 하이볼 섹션도 제외한다 (2026-10-04 결정. 평가셋 labels_v1에는 하이볼 섹션이 없어 점수에 영향 없음)

항목 순서는 채점하지 않는다.

## 값 규칙

| 케이스 | 규칙 | 예 |
| --- | --- | --- |
| 가격 약식 표기 | 문맥(다른 가격 크기, 잔/병, 열 제목)으로 실제 원 단위로 환산 | 잔 "1.6" → 16000, 병 "57" → 570000, 잔 "13" → 13000 |
| 단위를 확신할 수 없음 | price_krw null (평가셋에는 note에 이유) | "가격 '3.5'가 만원 단위인지 확신 불가" |
| 변동 가격 | null | "시가", "20.+α" |
| 잔·병 동시 표기 | unit별 항목 2개, 같은 raw_name | "2.8 / 57" → glass 28000, bottle 570000 |
| unit이 섹션·열 제목에만 있음 | 하위 항목 전체에 적용 | "한 잔" 섹션 → 전부 glass |
| 열 제목 없는 가격 두 개 | 작은 값 = glass, 큰 값 = bottle | "13  210" → glass 13000, bottle 210000 |
| 용량 각주 | 그 각주가 가리키는 항목에만 적용 | "세트의 각 잔은 20ml" → 단품에는 null |
| 한/영 병기 | 항목 1개, raw_name에 둘 다 | "글렌그란트 18년 / Glen Grant 18Y" |

## 검수 전 OCR 대조 (v2.3)

새 바(또는 새 사진)의 라벨 초안을 사람이 검수하기 **전에** 돌린다. 목적은 하나다: raw_name이 메뉴판 인쇄와 글자 단위로 같은지 확인한다. 표준 표기·외래어 표기법으로 고치지 않고, 인쇄가 오타여도 인쇄를 따른다.

1. 사진을 CLOVA OCR(표 인식 off)로 한 번 읽어 캐시에 둔다: `python ai/ocr/clova.py --set <세트> --variants off`. 응답은 레포 밖 `<data_dir>/ocr_cache/`에 저장되고, 캐시가 있으면 API를 다시 부르지 않는다. 지금 `clova.py`는 `val`·`test` 세트만 알고 있으므로, 새 사진 폴더는 `PHOTO_SETS`에 먼저 등록한다.
2. 대조 페이지를 만든다:
   ```
   python ai/eval/label_ocr_check.py --labels eval/<새 라벨>.json --photos <data_dir>/<사진 폴더> --out review/<이름>.html
   ```
   라벨 이름을 토큰으로 나눠, 사진 OCR 전체에 없는 토큰만 가장 가까운 OCR 글자열과 짝지어 패턴("라벨 → OCR")별로 보여 준다. 패턴마다 사진 크롭(빨간 상자)이 붙는다. 페이지에는 사진이 들어가므로 커밋하지 않는다(`review/*.html`은 `.gitignore` 대상).
3. 패턴마다 크롭을 보고 분류한다(결정 파일 JSON, `--decisions`로 다시 넣으면 분류별로 묶인다):
   - **B 라벨이 인쇄와 다름** → 라벨을 인쇄대로 고친다
   - **A CLOVA 오독** → 라벨 유지 (예: 산세리프 `Ila`를 `lla`로 읽음, 어두운 사진의 ㅔ/ㅖ)
   - **D 판독 불확실** → 원본 사진을 확대해 사람이 판독한 뒤 A 또는 B
   - 문장부호도 인쇄를 따른다 (예: Beck 메뉴판은 `Rowan`s`처럼 백틱이 인쇄돼 있어 백틱 유지)
4. 그다음 평소대로 사람이 전체 검수한다. 대조 결과(B 건수)는 라벨 파일 `labeling` 필드에 적는다.

한계: 사진 어딘가에 같은 표기가 인쇄돼 있으면 그 토큰은 걸리지 않는다. 브랜드 제목을 붙인 이름(v2.2 규칙)은 제목 토큰이 다른 줄에서 찾아지므로 문제없다. OCR이 아예 못 읽은 토큰은 "OCR에 없음"으로 따로 나온다.

## 예시 (평가셋이 아닌 온라인 메뉴판에서)

`data/fewshot/fewshot_78_kr_en_glass_bottle.png` 첫 줄 "글렌그란트 18년 | Glen Grant 18Y | 2.8 / 57":

```json
{"raw_name": "글렌그란트 18년 / Glen Grant 18Y", "price_krw": 28000, "pour_ml": null, "unit": "glass"}
{"raw_name": "글렌그란트 18년 / Glen Grant 18Y", "price_krw": 570000, "pour_ml": null, "unit": "bottle"}
```

같은 사진의 "글렌알라키 18년 | GlenAllachie 18Y | 3.9 / -" → glass 항목 1개만.

`data/fewshot/fewshot_hanjan_korean_2col.png` ("한 잔" 섹션) "글렌파클라스105 CS  2.7":

```json
{"raw_name": "글렌파클라스105 CS", "price_krw": 27000, "pour_ml": null, "unit": "glass"}
```

`data/fewshot/fewshot_tot_tasting_sets.jpg`는 전부 테이스팅 세트라 항목이 0개다.
