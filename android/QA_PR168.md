# BottleMap Android PR #168 — Galaxy S23 QA 가이드

검증 범위: **Android만**. 서버는 병합된 PR #164를 사용하며, AI 인식 정확도 자체는 Android 합격 기준이 아니다. 이 가이드는 인식된 결과를 Android에서 확인·수정·게시했을 때의 동작을 검사한다.

- 브랜치: `feature/i4-p14-p32-p33-android-integration`
- PR: https://github.com/snuhcs-course/swpp-2026-project-team-19/pull/168
- 대상 기기: Galaxy S23. 가능하면 글꼴 1.3~1.5배, 작은 표시 크기에서도 반복한다.
- 서버: `https://bottlemap.o-r.kr/` — **GitHub PR #164 Merge는 실제 배포 확인이 아니다.**
- QA 이미지: 대화에서 제공한 `BottleMap_OCR_QA_Menu_A.jpg`, `_B.jpg`, `_C.jpg`를 갤러리 또는 Downloads에 저장한다. 이미지에 적힌 가격이 기준값이다. 테스트용 가상 데이터이므로 실영업 매장에 게시하지 않는다.

## 0. 사전 준비

1. 테스트 전용 Owner 계정과 **테스트 전용 매장**을 사용한다. 실제 매장 공개 데이터는 손상하지 않는다.
2. Git 루트 PowerShell:

   ```powershell
   git fetch origin
   git switch feature/i4-p14-p32-p33-android-integration
   git pull --ff-only
   .\gradlew.bat :app:installDebug "-PBOTTLEMAP_API_BASE_URL=https://bottlemap.o-r.kr/"
   ```

3. **앱 데이터 삭제나 재설치 대신 기존 앱 위에 업데이트**하여 로컬 Draft 보존을 확인한다. 앱 삭제/데이터 초기화는 Draft를 지울 수 있다.
4. 각 게시 실험 전 테스트 매장의 기존 메뉴 목록·가격·옵션 수와 진행 중인 import 유무를 기록한다. A/B/C 조합을 서로 다른 신규 import로 실험하려면 기존 import를 완료/취소해야 한다.
5. 앱이 `kind: Extra inputs are not permitted`를 반환하면 서버 배포 SHA/OpenAPI 확인으로 분류한다. **Android에서 `kind`를 빼서 해결하지 않는다.**

### C — 병/Bottle 통일 검증

| 메뉴 | 원본 옵션 | 가격 |
|---|---|---:|
| 글렌피딕 12년 | **Bottle** | **150,000원** (A의 `병`과 같은 병 옵션, 가격 충돌) |
| 글렌피딕 12년 | 잔 30ml | 12,000원 |
| 글렌피딕 12년 | 샷 30ml | 15,000원 |
| 맥주 2 | Bottle 500ml | 7,500원 |

**중요:** A/C에는 일부러 **30ml 중복·상충 가격**을 넣었다. Android는 서버가 동일 위스키를 여러 `extractedItemId`로 반환하더라도 상품 ID/확인된 이름을 기준으로 **한 카드**에 모아 보여준다. 서로 다른 30ml 가격은 한 카드에서 하나만 선택한다. 별도 60ml/Bottle은 검수할 문제가 없다면 자동 포함된다. 병합된 카드에서 게시할 옵션은 대표 OCR 항목으로 보내고, 원본의 나머지 항목 ID에는 별도 reject 결정을 보낸다. Backend A4의 자동 그룹핑은 여전히 미구현이며, 서로 다른 위스키를 잘못 하나로 묶는 경우는 Android 실패로 기록한다.

## 2. 직접 메뉴 등록 QA

- [ ] D01 Customer 검색·지도·매장 상세 접근: 기존 데이터가 정상 표시된다.

- [ ] D04 승인된 위스키 검색·선택·가격 수정: 실제 `productId` 연결과 재진입 후 가격 유지.

- [ ] D06 기존 메뉴 `위스키 ↔ 기타 주류` 변경: 삭제 후 새로 등록하라는 안내, 원래 행 보존.
- [ ] D07 사진으로 등록한 서로 다른 용량의 옵션 4개 이상 행: 직접 PUT 편집 차단, 기존 가격 옵션은 삭제되지 않는다.

## 3. 사진 검수 QA

- [ ] P01 A 한 장 업로드: **OCR 단계의 오차**와 **Android 검수 단계의 오차**를 별도로 기록. 원본 사진 확대/크롭 확인.
- [ ] P02 A의 잔 30ml(12,000원)와 샷 30ml(15,000원): **같은 위스키 한 카드**에서 30ml 가격을 선택한다. 기존 매장 30ml가 있으면 [기존 가격] [New 잔 표시 가격] [New 샷 표시 가격], 없으면 New 두 가격만 표시한다. 60ml/Bottle은 그대로 자동 포함되고 별도 중복 카드/제외 안내가 없어야 한다.
- [ ] P03 A의 `병`: 검수 화면·Customer·Owner 화면에는 **Bottle**. 최종 게시 시 다른 병 옵션으로 중복되지 않고 OCR 원본 ID를 유지한다.
- [ ] P04 비위스키 자동 추출은 AI/Backend 후속 Issue #169로 보류한다. 현재 검수의 자동 추출 성공으로 판단하지 않으며, 직접 메뉴 추가 기능은 별도로 테스트한다.
- [ ] P05 한 위스키에서 4개 이상의 서로 다른 용량을 OCR이 감지하면 "용량은 최대 3가지까지 설정 가능해요."와 세로형 [30ml 12,000원] 등의 버튼 목록이 나온다. 최대 3개 선택 후 확인해야 최종 옵션으로 확정된다.
- [ ] P06 A+B를 **하나의 import**에 넣기: 글렌피딕 12년이 한 카드에 나타나고 30ml의 사진별 가격만 비교할 수 있어야 한다. 다른 고유 용량은 최대 3개 선택 과정에서 명시적으로 결정되며 숨겨진 값이 중복 게시되지 않는다.
- [ ] P07 A+C를 **하나의 import**에 넣기: `병`과 `Bottle`은 같은 Bottle 한 옵션의 가격 후보로 판단한다. 30ml 잔/샷도 같은 용량 가격 후보이며, 검수 카드가 중복 생성되지 않는다. 과거 서버 중복행 자동 마이그레이션을 의미하지 않는다.
- [ ] P08 신규 미연결 위스키: 매장 메뉴 게시, 운영자 확인 후 검색된다는 안내. A3 승인이 완료되지 않았다면 공용 검색 노출은 기대하지 않는다.
- [ ] P09 빈 메뉴 이름: OCR 원문 가격 문장을 이름으로 자동 사용하지 않으며 직접 입력하도록 안내한다.
- [ ] P10 기본 잔 용량 30→45ml: 기본값을 적용한 잔만 갱신, 직접 입력한 60ml·Bottle은 변경되지 않는다.
- [ ] P11 게시 버튼 연타: 동일한 import를 두 번 게시하지 않는다. 게시 성공 후 검수 화면이 사라지고 메뉴 관리로 돌아가야 하며 `검수할 메뉴판 작업이 없어요`/무반응 재시도 화면이 나타나지 않아야 한다.
- [ ] P12 로컬 Draft: 이름·가격을 수정하고 앱 강제 종료 후 같은 import에 재진입하여 수정 상태가 유지되는지 확인한다. **서버 Draft(A5)와 구분한다.**
- [ ] P13 네트워크 실패/409: 잘못된 성공 토스트가 없고 검수 내용이 삭제되지 않으며 다시 불러오기·재시도가 가능하다.
